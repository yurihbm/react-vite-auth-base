# i18n

- Namespaces are the JSON files in `public/locales/<lng>/` (`shared` is the default, plus `auth`, `home`, `errors`). Supported languages and the fallback are in `src/lib/i18n/constants.ts`; every key must exist in every language folder (`en`, `pt`).
- Components call `useTranslate("<namespace>")` (or `useTranslateKeyState`, `translationKey`) from `@lib/i18n`; keys are typed from `src/lib/i18n/generated/`.
- After adding or changing keys run `pnpm i18n`: it extracts keys from `src/**/*.{ts,tsx}` into the JSON files and regenerates `generated/i18n.d.ts` and `resources.d.ts`. Commit both. Keys that are only built dynamically must be declared with `translationKey<"ns">("ns:key")` so the extractor keeps them (see `src/lib/api/error-keys.ts`).
- Translate the new keys in the other language files; do not leave extractor placeholders.
- In tests the i18n instance has no resources and `nsSeparator` off, so `t("loginForm.submitButton")` renders the raw key; assert on keys.
- Libs stay app-agnostic: app copy belongs to modules and routes, not to `src/lib/ui`.
